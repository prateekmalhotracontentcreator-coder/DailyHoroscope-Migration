## Key Architecture Notes

### Remedy Display Pattern (KP — target state after next fix)
```python
# Backend _summary_report — bundle first, Engine fallback:
if answer.behavioral_remedy:
    report["behavioral_remedy"] = answer.behavioral_remedy      # primary
elif ritual_remedy_doc:
    report["behavioral_remedy"] = ritual_remedy_doc.get("ritual_remedy")  # fallback

# _resolve_kp_remedy_doc called ONLY when bundle fields are empty AND remedy_ref exists
```

### Mandatory Architecture Rules (all 9)
1. ALL live astronomical/dasha data from `vedic_calculator.py` + `pyswisseph` — never replicate
2. `knowledge_rules` always filtered by `science_id`
3. All notifications via existing `/api/notifications/trigger/{type}` — never direct push/WA
4. Remedies Engine downstream-only for KP — never overrides KP verdict
5. Commit format: `feat(scope):` / `fix(scope):` / `chore(scope):`
6. Bump `ENGINE_VERSION` in `panchang_router.py` before any backend change
7. All fetch calls: `withCredentials: true` / `credentials: 'include'`
8. Never spread `...form` into API payloads when backend model uses `extra="forbid"`
9. FastAPI 422 `detail` is an array — always guard with `typeof detail === "string"`
