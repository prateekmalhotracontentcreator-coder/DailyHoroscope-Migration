**New helper functions:**
- `_context_score()` — safely extracts float from `ContextSignal | float` (handles dict and object patterns)
- `_confidence_band()` — float → "LOW" / "MEDIUM" / "HIGH" / "VERIFIED" string
- `_category_to_domain()` — maps `categories` field values to Arc Angel domain names via `ARC_ANGEL_DOMAIN_MAP`
- `_normalize_domain_name()` — reverse lookup from domain label back to canonical name
- `_extract_lucky_elements()` — builds lucky_elements dict from top matched rules + chart dasha
- `_extract_timing_window()` — extracts maha/antar dasha string from chart overview
- `_select_bridge_phrases()` — selects bridge phrases from `NarrativeBridgeDocument` records; injects a default "contrast" phrase if tension_blocks are present but no bridge documents exist yet
- `_build_domain_plan()` — groups matched rules by Arc Angel domain; separates backbone vs support rules; attaches tension blocks; builds planner payload list ordered by `DOMAIN_PRIORITY`
- `_compact_rule_payload()` — strips heavy fields from rules before sending to Claude (limits passages to 2, keeps key metadata)
- `_extract_text_from_claude_response()` — extracts text from Anthropic SDK response object
- `_parse_json_payload()` — parses Claude JSON response, handles triple-backtick code block wrapping
- `_build_narrative_system_prompt()` — builds system prompt with WIM rules + author voice + bridge phrases
- `_build_narrative_user_prompt()` — builds JSON user message with backbone_science_id, α/β/γ scores, domain plan
- `_coerce_narratives()` — validates and normalises Claude's `narratives` list into `KnowledgeNarrativeDomain` objects

**`KnowledgeEngine.generate_narrative()` method (lines 808–920):**
- Accepts: `matched_rules`, `chart`, `context`, `user_context`, `author_voice_id`, `tension_blocks`, `model`
- Merges tension_blocks from both `context.tension_blocks` and direct argument
- Calls `_build_domain_plan()` to structure the prompt
- Loads author voice from MongoDB (`author_voices` collection) with fallback chain
- Loads bridge phrases from MongoDB (`narrative_bridges` collection)
- Calls Claude API (`AsyncAnthropic`) at `temperature=0.35`, `max_tokens=2400`
- Returns `KnowledgeNarrativeResponse` with structured error on any failure (never raises 500)
- `_anthropic_client()` — lazy import of `anthropic.AsyncAnthropic`; returns `None` gracefully if package absent or `ANTHROPIC_API_KEY` not set

**Module-level convenience functions (lines 969–977):**
- `scan_chart()` — top-level function wrapping `get_default_knowledge_engine().scan_chart()`

## 4. After Item 4 Fix — Send Codex Green Light for Item 5

**CPath-1 Item 5: Library Console — Rules Browser + Import UI**

Per the contract (Section 21 CPath-1 sequence), item 5 is the Library Console. This is a new Admin Console tab.

**Spec for the Codex brief:**

**Backend routes to build (in a new `knowledge_router.py`):**
- `GET /api/knowledge/rules` — list approved/pending rules (paginated, filterable by science_id, categories, approval_status, strength_band)
- `GET /api/knowledge/rules/{rule_id}` — get single rule
- `PATCH /api/knowledge/rules/{rule_id}/approve` — set approval_status = "approved"
- `PATCH /api/knowledge/rules/{rule_id}/reject` — set approval_status = "rejected"
- `GET /api/knowledge/import-batches` — list import batches
- `GET /api/knowledge/import-batches/{batch_id}` — get batch + stats
- `POST /api/knowledge/import-batches/{batch_id}/approve-all` — bulk approve all rules in batch
- `GET /api/knowledge/index/status` — proxy to `engine.index_refresh_status()`
- `POST /api/knowledge/index/refresh` — trigger `engine.schedule_index_refresh()`; return `index_refreshed` boolean

**Frontend (`frontend/src/pages/LibraryConsolePage.jsx`):**
- Route: `/admin/library` (gated behind admin auth)
- 3 sub-tabs: **Rules Browser** / **Import Batches** / **Index Status**
- Rules Browser: table with columns (rule_id, science_id, categories, strength_band, approval_status, score preview); row actions: Approve / Reject / View full rule
- Import Batches: list of batches with status, rule_count, import_date; "Approve All" button per batch
- Index Status: shows rule_count, built_at, index_refreshed boolean; "Refresh Index" button (triggers POST → polls status)
- Theme: Temple App tokens (`bg-card`, `text-gold`, `border-gold/20`, GlassCard pattern)

**Important constraints:**
- Frontend must poll `GET /api/knowledge/index/status` after triggering refresh until `index_refreshed: true` (Strategy C — stale reads tolerated; Library Console waits for confirmation before showing "batch live")
- Per-rule `approval_status` field is already on `InterpretationRuleDocument` (added in item 1 Temple Team fix)
- `APPROVED_RULE_FILTER = {"active": True, "approval_status": "approved"}` — only approved + active rules enter the index

```
Data Layer (MongoDB)     →  Rule Engine (Python)         →  Narrative Layer (Claude API)
interpretation_rules     →  KnowledgeIndexStore          →  generate_narrative()
author_voices            →  scan_chart()                  →  _build_narrative_system_prompt()
narrative_bridges        →  _condition_matches()          →  AsyncAnthropic.messages.create()
import_batches           →  _score_rule()                 →  KnowledgeNarrativeResponse
```
